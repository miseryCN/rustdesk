# RustDesk 桌面端多服务器配置切换设计

## 目标

为 RustDesk 桌面客户端增加多个服务器配置档案，并允许用户在主页快速切换。切换不重启应用，不主动断开已经建立的远程控制或文件传输会话，并立即影响后续连接和本机 rendezvous 注册。

每个配置档案独立保存该服务器下的最近连接设备以及对应的连接凭据、别名和连接选项，避免不同服务器出现相同设备 ID 时发生数据冲突。

## 范围

首版支持 Windows、Linux 和 macOS 桌面端。

每个服务器配置档案只包含：

- 稳定且不可变的内部 ID；
- 用户可修改的显示名称；
- ID Server；
- Key。

首版不包含：

- Android 和 iOS；
- RustDesk 账号、API Server 或账号地址簿；
- 云端同步；
- Relay Server 的独立配置；
- 跨设备自动同步配置档案或最近连接记录。

切换配置时，`relay-server` 和 `api-server` 保持为空。Relay 地址继续由所选 ID Server 的响应提供；本功能不调用任何依赖 API Server 的账号能力。

## 用户体验

### 主页快速切换

桌面主页连接区域右上角显示当前服务器档案，内容包括状态圆点、档案名称和下拉箭头。

用户点击后看到所有服务器档案：

- 当前档案带选中标记；
- 点击其他档案立即开始切换；
- 菜单底部提供“管理服务器配置”入口。

切换期间，入口显示“连接中”状态并禁止重复点击。切换完成后：

- 当前档案名称立即更新；
- 主页最近连接列表清空并加载目标档案的数据；
- 远程 ID 自动完成列表改用目标档案的数据；
- 后续新连接使用目标档案的 ID Server 和 Key；
- 已经建立的会话继续运行。

若目标服务器不可达，档案仍保持为当前档案，状态显示“未就绪”。用户可以编辑该档案或切换到其他档案。系统不因临时网络故障自动回滚选择。

### 配置管理

配置管理界面支持新增、编辑和删除档案。

- 名称去除首尾空白后不能为空，并且按不区分大小写的结果在本机档案列表中唯一；
- ID Server 去除首尾空白和末尾 `/`，接受主机名、IPv4、带方括号的 IPv6，以及以上形式加端口；空值表示使用 RustDesk 公共服务器；
- 保存只进行地址格式校验，不以网络是否可达作为保存条件；管理界面另提供“测试连接”，测试失败不阻止保存；
- Key 去除首尾空白后保存，允许为空，以兼容公共服务器和未配置公钥的私有服务器；
- 编辑当前档案的 ID Server 或 Key 后立即重新应用，无需重启应用；
- 当前档案不可直接删除，必须先切换到其他档案；
- 至少保留一个档案；
- 删除非当前档案前明确提示其最近设备、密码、别名和连接选项也会被永久删除。

档案名称仅用于显示。重命名不会改变内部 ID，也不会影响该档案已有的设备数据。

## 数据模型与磁盘结构

### 服务器档案

新增版本化的服务器档案配置：

```text
ServerProfilesConfig
  version: u32
  active_profile_id: String
  profiles: Vec<ServerProfile>

ServerProfile
  id: String
  name: String
  id_server: String
  key: String
```

配置保存在 RustDesk 平台配置目录下的独立文件 `RustDesk_server_profiles.toml`。新建档案使用 UUID 作为内部 ID；首次迁移的档案固定使用 `default`，从而让中断后的迁移能够安全重试。

写入采用“临时文件 + 同目录原子替换”。如果写入失败，内存中的当前档案和现有 RustDesk 网络配置保持不变，并向 UI 返回可显示的错误。

### 最近设备与凭据

现有 `PeerConfig` 以设备 ID 为唯一磁盘键。它需要增加配置档案命名空间：

```text
peer_profiles/
  <profile_id>/
    peers/
      <encoded_device_id>.toml
```

每个 peer 文件继续使用现有 `PeerConfig` 格式和现有密码加密逻辑，包含密码、别名、远端信息、画质、窗口状态、端口转发和其他连接选项。服务器 Key 不属于连接密码，保存在服务器档案配置中。

`hbb_common::config::PeerConfig` 增加显式接收 `profile_id` 的读取、写入、删除和枚举接口。现有无 profile 参数的接口仅作为迁移兼容层，内部使用当前活动档案；所有会话相关路径必须使用显式接口。

## 运行时组件

### ServerProfileManager

Rust 主进程新增 `ServerProfileManager`，负责：

- 加载、校验和原子保存档案配置；
- 暴露列表、当前档案、新增、编辑、删除和切换操作；
- 将当前档案的 `id_server` 和 `key` 批量应用到现有 Config options；
- 清空 `relay-server` 和 `api-server`；
- 通过现有 IPC 配置同步机制让已安装服务收到变更；
- 让 rendezvous mediator 只重启一次；
- 向 Flutter 返回结构化成功或错误结果。

网络配置的兼容真值仍是现有 options：

- `custom-rendezvous-server`；
- `key`；
- `relay-server`；
- `api-server`。

这保证未适配配置档案的现有 RustDesk 网络代码继续工作。服务器档案文件负责管理多个候选值和当前选择，切换时再把选择写入现有 options。

### Flutter 模型

Flutter 桌面端新增响应式服务器档案模型，负责：

- 获取档案列表和当前档案；
- 驱动主页快速切换入口和管理对话框；
- 串行化切换请求，防止快速重复点击；
- 在成功切换后清空并重新加载最近设备模型和自动完成缓存；
- 显示 Rust 层返回的验证、持久化和切换错误。

移动端不展示入口，也不调用新增接口。

## 切换流程

1. Flutter 请求切换到目标 `profile_id`。
2. Rust 校验目标档案存在且不是当前档案。
3. Rust 准备新的档案配置和网络 options，但尚不改变内存状态。
4. Rust 原子保存新的 `active_profile_id`。
5. Rust 批量应用 `custom-rendezvous-server`、`key`、空的 `relay-server` 和空的 `api-server`。
6. 桌面服务通过现有 IPC 变更检测重启 rendezvous mediator；批量更新只触发一次重启。
7. Rust 更新当前 peer profile 上下文并向 Flutter 返回成功。
8. Flutter 更新当前档案显示，清空旧列表，并调用 profile-aware 的 recent peers 加载接口。

如果步骤 4 失败，网络 options 不发生变化。如果步骤 5 发生不可恢复的本地写入错误，Rust 尝试恢复旧 `active_profile_id` 和旧 options，并返回错误。服务器不可达不属于本地切换失败，不触发回滚。

## 活动会话不掉线保证

Rendezvous mediator 的重启只结束并重建注册循环；它不关闭已经创建的远程数据连接。切换流程不得调用关闭会话、关闭 Server 连接或重启整个进程的接口。

每个新会话创建时捕获当时的 `profile_id`，并将其保存在会话的 `LoginConfigHandler` 或等价会话上下文中。会话生命周期内的所有 `PeerConfig` 读写都使用捕获的 `profile_id`，包括：

- 读取已保存密码；
- 记住或忘记密码；
- 保存远端主机信息；
- 保存别名和会话选项；
- 会话结束后的配置写回。

因此，用户切换到新档案后，旧会话仍向原档案写入数据，不会污染新档案。切换后创建的新会话捕获新的活动档案。

## 首次迁移与兼容性

当 `RustDesk_server_profiles.toml` 不存在时执行一次幂等迁移：

1. 从现有 options 读取 `custom-rendezvous-server` 和 `key`；
2. 创建内部 ID 为 `default`、名称为“默认配置”的档案；
3. 将现有 `peers` 目录迁移到 `peer_profiles/default/peers`；
4. 原子保存档案配置，并将 `default` 设为当前档案；
5. 重新加载最近设备，确认原有记录可见。

迁移使用固定目标目录并检查源、目标状态：

- 只有源目录存在时，移动源目录；
- 只有目标目录存在时，认为目录迁移已完成；
- 两者都不存在时，创建空目标目录；
- 两者都存在时，逐文件合并，目标文件优先，保留无法自动合并的源文件并记录错误。

档案配置只有在 peer 目录准备完成后才写入。迁移中断后，下次启动根据以上规则继续，不删除尚未确认迁移成功的源数据。

没有服务器档案功能的旧版本仍能读取原有主配置，但无法发现新的 `peer_profiles` 目录。首版不承诺降级后显示新档案中的最近设备；用户数据文件保持在磁盘上，不会被降级版本删除。

## 错误处理

- 配置文件损坏：保留损坏文件的备份副本，显示错误，不自动覆盖；若现有 options 可用，允许用户创建新的档案配置。
- 档案写入失败：不改变当前档案，不重启 mediator，返回错误。
- PeerConfig 单文件损坏：沿用现有容错行为，跳过该设备并记录日志，不影响其他设备。
- 服务器地址格式错误：保存前阻止并在字段下显示错误。
- 服务器离线：允许保存和切换，通过现有连接状态显示“未就绪”。
- 重复名称：保存前阻止，并提示选择其他名称。
- 重复切换：Flutter 在首个请求完成前禁用选择器；Rust 同时串行化切换操作。
- 删除数据失败：不删除档案条目，返回错误，避免产生无法管理的孤立数据。

日志不得输出连接密码。服务器 Key 沿用项目现有日志策略，不新增明文调试输出。

## 测试策略

### Rust 单元测试

- 档案配置序列化、反序列化和版本校验；
- 新增、编辑、重命名、删除和唯一名称校验；
- 当前档案不可删除且至少保留一个档案；
- 原子保存失败时内存状态不变化；
- 首次迁移的四种源/目标目录状态；
- 相同设备 ID 在两个 profile 下读取不同 PeerConfig；
- 密码通过现有加密路径落盘，日志与序列化错误不泄漏明文；
- 活动会话捕获 profile 后，切换全局 profile 仍写回原目录；
- 批量应用 options 只触发一次 mediator 重启信号。

### Flutter 测试

- 主页显示当前档案；
- 下拉菜单选择目标档案后显示忙碌状态并防止重复提交；
- 成功切换后刷新最近设备和自动完成列表；
- 失败时保留原档案显示并展示错误；
- 新增、编辑和删除管理流程；
- 当前档案删除入口被禁用；
- 服务器离线时档案仍切换成功，状态随后显示未就绪。

### 集成验证

在 Windows、Linux 和 macOS 上至少验证：

1. 从已有 RustDesk 配置升级后，原最近设备和密码仍可用；
2. 两个服务器存在相同设备 ID 时，各自显示并使用自己的密码；
3. 打开一个远程会话后切换服务器，旧会话不掉线；
4. 切换后从主页发起的新连接使用新服务器；
5. 切回旧服务器后，原设备列表、别名和密码恢复；
6. 应用退出并重新启动后，最后选择的档案仍为当前档案。

## 完成标准

功能完成必须同时满足：

- 桌面主页可以在不重启软件的情况下快速切换服务器档案；
- 切换后新连接和本机注册立即使用新 ID Server 和 Key；
- 切换不主动关闭任何已建立会话；
- 最近设备与连接凭据按档案隔离并可在切回后恢复；
- 首次升级不丢失现有最近设备和连接凭据；
- Rust 和 Flutter 自动化测试通过；
- Windows、Linux 和 macOS 的目标构建或对应 CI 检查通过。
